# ScreenFry

Read `docs/PROJECT_BRIEF.md`, `README.md`, and the relevant architecture/testing docs before changing behavior.

- The one working copy on Sam's Mac is `~/ScreenFry` (repository: https://github.com/yasserjaghoori/ScreenFry). Work only there; don't create or use copies elsewhere, such as under `Documents/ChatGPT`.
- This is Sam and Yasser's productivity project. Start with Chrome and Safari extensions; a native macOS companion and iOS app are later phases.
- Preserve local-first operation: Phase 1 has no backend, accounts, analytics, or API keys.
- Keep policy decisions in `packages/policy-engine` and state changes in `packages/core`; UI controls alone must not enforce limits or authorize edits.
- Scope: YouTube, Instagram, X, Reddit, Substack, TikTok, Facebook, LinkedIn and Quora (the last four added at the user's request), defined in the single site registry (`siteDefinitions`; see `docs/ADDING_A_SITE.md`). No general browsing history: measure time only on sites with a rule; optional settings password, no mandatory PINs/overrides/commitments. Windows live on their own page: allow windows (sites usable only inside) block windows (sites blocked inside, user-requested) and Fry Time windows ("free" mode in code: each website's feed blocking paused inside for its own daily minutes, the same for all or custom per website, then that website is back to normal; user-requested); contradicting windows (a block window overlapping an allow or free-time window on the same site) are saved but both pause until one is edited (user-requested), and free time never unblocks a site or lifts a limit. The Earn page (user-requested, beside Websites and Windows) holds earn goals (either unlock: locked sites blocked each day until a goal site has had its minutes, or fry: each completion earns Fry Time on chosen sites, the same each time or different each time (1st, 2nd, 3rd…), repeating up to a daily count or without limit; earned Fry Time is one pool per goal shared by its sites, cumulative across completions, apart from windows' minutes and usable outside windows; only active time (tab in front, user not idle, ScreenFry's popup closed) counts toward goals; strict goals reset their progress toward the next completion when the user leaves; earning shows an in-page notice; no goal site may be locked by an unlocking goal). The Experimental page holds loadouts (five setups; the active one is the live settings; a share code holds one loadout as a compact `SF2-` encoding of only non-default settings, is previewed as per-website change slides, and is applied through core actions). The Mac app keeps its own five loadouts as share codes (saved from a browser's check-in, pasted, or sent to every browser through the bridge; a password-protected browser asks for its password before applying); it has no other settings import/export, and there is no feed blocking master switch (user-requested). Fry Time does nothing on a site with no filters on or a blocked site.
- Count focused usage plus actual background playback; deduplicate simultaneous tabs per website.
- Keep feed blocking scoped to distraction surfaces, preserving useful search and direct links. Shorts entry points must not reopen the infinite-scroll loop.
- Never claim the extension can prevent removal or share state between browsers. Native Screen Time capabilities need separate investigation.
- Use Node from `.nvmrc` and `npm ci`. Run `npm run check` after code changes and `npm run test:e2e` for extension integration changes.
- Builds share `dist/chrome`; do not run a build while the Chrome smoke test is using it. Run `npm run build:safari` before regenerating or building the Safari project.
- Do not commit personal message exports, browsing data, passwords, signing identities, or generated build output. Work on a `codex/` branch and preserve collaborators' changes.
