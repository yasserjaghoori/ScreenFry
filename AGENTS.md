# ScreenFry

Read `docs/PROJECT_BRIEF.md`, `README.md`, and the relevant architecture/testing docs before changing behavior.

- The one working copy on Sam's Mac is `~/ScreenFry` (repository: https://github.com/yasserjaghoori/ScreenFry). Work only there; don't create or use copies elsewhere, such as under `Documents/ChatGPT`.
- This is Sam and Yasser's productivity project. Start with Chrome and Safari extensions; a native macOS companion and iOS app are later phases.
- Preserve local-first operation: Phase 1 has no backend, accounts, analytics, or API keys.
- Keep policy decisions in `packages/policy-engine` and state changes in `packages/core`; UI controls alone must not enforce limits or authorize edits.
- Scope: YouTube, Instagram, X, Reddit, Substack, TikTok, Facebook and LinkedIn (the last three added at the user's request), defined in the single site registry (`siteDefinitions`; see `docs/ADDING_A_SITE.md`). No general browsing history: measure time only on sites with a rule; optional settings password, no mandatory PINs/overrides/commitments. Windows live on their own page: allow windows (sites usable only inside) block windows (sites blocked inside, user-requested) and Fry Time windows ("free" mode in code: each website's feed blocking paused inside for its own daily minutes, the same for all or custom per website, then that website is back to normal; user-requested); contradicting windows (a block window overlapping an allow or free-time window on the same site) are saved but both pause until one is edited (user-requested), and free time never unblocks a site or lifts a limit. The Experimental page (user-requested) holds earn goals (either unlock: locked sites blocked each day until a goal site has had its minutes, or fry: each completion earns Fry Time on chosen sites, repeating up to a daily count or without limit; goal sites are measured like rule sites, and no goal site may be locked by an unlocking goal) and loadouts (five setups; the active one is the live settings; a share code holds one loadout as a compact `SF2-` encoding of only non-default settings, is previewed as per-website change slides, and is applied through core actions). There is no settings import/export in the Mac app and no feed blocking master switch (user-requested).
- Count focused usage plus actual background playback; deduplicate simultaneous tabs per website.
- Keep feed blocking scoped to distraction surfaces, preserving useful search and direct links. Shorts entry points must not reopen the infinite-scroll loop.
- Never claim the extension can prevent removal or share state between browsers. Native Screen Time capabilities need separate investigation.
- Use Node from `.nvmrc` and `npm ci`. Run `npm run check` after code changes and `npm run test:e2e` for extension integration changes.
- Builds share `dist/chrome`; do not run a build while the Chrome smoke test is using it. Run `npm run build:safari` before regenerating or building the Safari project.
- Do not commit personal message exports, browsing data, passwords, signing identities, or generated build output. Work on a `codex/` branch and preserve collaborators' changes.
