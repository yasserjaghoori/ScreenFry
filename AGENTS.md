# ScreenFry

Read `docs/PROJECT_BRIEF.md`, `README.md`, and the relevant architecture/testing docs before changing behavior.

**On `dev/next`** (unreleased features, user-requested): read `docs/NEXT.md` first. It's the plan for the Chrome Web Store extension, the installer's two choices (official vs. developer extensions), the setup library and search, and the Earn leaderboard. `main` is the released app; merge `origin/main` into this branch at the start of each session, ship finished pieces to `main` by pull request, and never run the Release workflow from here (it refuses). The community features may use the backend described in `docs/NEXT.md`, opt-in only; everything else below still applies.

- The one working copy on Sam's Mac is `~/ScreenFry` (repository: https://github.com/yasserjaghoori/ScreenFry). Work only there; don't create or use copies elsewhere, such as under `Documents/ChatGPT`.
- This is Sam and Yasser's productivity project. Start with Chrome and Safari extensions; a native macOS companion and iOS app are later phases.
- Preserve local-first operation: Phase 1 has no backend, accounts, analytics, or API keys.
- Keep policy decisions in `packages/policy-engine` and state changes in `packages/core`; UI controls alone must not enforce limits or authorize edits.
- Scope: YouTube, Instagram, X, Reddit, Substack, TikTok, Facebook, LinkedIn and Quora (the last four added at the user's request), defined in the single site registry (`siteDefinitions`; see `docs/ADDING_A_SITE.md`). No general browsing history: measure time only on sites with a rule; optional settings password, no mandatory PINs/overrides/commitments. Windows live on their own page: allow windows (sites usable only inside) block windows (sites blocked inside, user-requested) and Fry Time windows ("free" mode in code: each website's feed blocking paused inside for its own daily minutes, the same for all or custom per website, then that website is back to normal; user-requested); contradicting windows (a block window overlapping an allow or free-time window on the same site) are saved but both pause until one is edited (user-requested), and free time never unblocks a site or lifts a limit. The Earn page (user-requested, beside Websites and Windows) holds earn goals (either unlock: locked sites blocked each day until a goal site has had its minutes, or fry: each completion earns Fry Time on chosen sites, the same each time or different each time (1st, 2nd, 3rd…), repeating up to a daily count or without limit; earned Fry Time is one pool per goal shared by its sites, cumulative across completions, apart from windows' minutes and usable outside windows; only active time (tab in front, user not idle, ScreenFry's popup closed) counts toward goals; strict goals reset their progress toward the next completion when the user leaves; earning shows an in-page notice; no goal site may be locked by an unlocking goal). The Share page (beside Earn) holds loadouts (five setups; the active one is the live settings; a share code holds one loadout as a compact `SF2-` encoding of only non-default settings, is previewed as per-website change slides, and is applied through core actions). Loadouts and share codes moving setups between browsers (a Safari setup into Chrome and back, through codes or the Mac app) is a deliberate feature (user-confirmed); never remove it. Loadouts can be renamed in the browsers and the Mac app. The Mac app keeps its own five loadouts, each holding every browser's setup as share codes (Save ScreenFry Setup saves them all from the browsers' check-ins; pasted codes; Use in All Browsers sends each browser its own through the bridge; a password-protected browser asks for its password before applying); it has no other settings import/export, and there is no feed blocking master switch (user-requested). Fry Time does nothing on a site with no filters on or a blocked site.
- Count focused usage plus actual background playback; deduplicate simultaneous tabs per website.
- Keep feed blocking scoped to distraction surfaces, preserving useful search and direct links. Shorts entry points must not reopen the infinite-scroll loop.
- Never claim the extension can prevent removal or share state between browsers. Native Screen Time capabilities need separate investigation.
- Every release's changes go in `CHANGELOG.md` (short, plain words, under "Unreleased" until the release names it; user-requested): the Mac app's update window and the GitHub release show them.
- Use Node from `.nvmrc` and `npm ci`. Run `npm run check` after code changes and `npm run test:e2e` for extension integration changes.
- Builds share `dist/chrome`; do not run a build while the Chrome smoke test is using it. Run `npm run build:safari` before regenerating or building the Safari project.
- Do not commit personal message exports, browsing data, passwords, signing identities, or generated build output. Work on a branch named `dev/<what it does>` (for example `dev/fix-chrome-status` or `dev/release-1.0.1`; unreleased features live on `dev/next`) and preserve collaborators' changes.
